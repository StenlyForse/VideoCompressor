## 1. Контекст и проблема

Сейчас, чтобы запустить приложение, нужно поставить .NET 10 SDK и FFmpeg и выполнить `dotnet run` в терминале. Для разработчика это нормально, для обычного человека — нет.

Ограничения, выбранные автором (2026-10-23):
- без установщика: регистрация в Microsoft Store недоступна, а неподписанный установщик вызывает недоверие;
- без автообновления: это утилита; новые версии скачиваются вручную со страницы релизов на GitHub;
- без платной подписи кода.

## 2. Цель

Готовый архив на странице релизов GitHub: **скачал → распаковал → запустил**, без установки .NET, FFmpeg и чего-либо ещё. Плюс максимум прозрачности, чтобы человек мог убедиться, что внутри нет ничего лишнего.

## 3. Не-цели

- Установщик, ярлыки в «Пуске», запись в «Программы и компоненты».
- Автообновление и любые сетевые запросы из приложения (NFR-001 v1 остаётся в силе без изменений).
- Microsoft Store, winget, подпись кода.
- Готовые сборки для macOS и Linux (там по-прежнему `dotnet run`, README).

## 4. Пользовательские сценарии

### US-1. Скачать и запустить (P1)

*Как обычный пользователь Windows, я хочу скачать архив, распаковать и сразу пользоваться.*

**Критерии приёмки:**
1. На странице релиза есть один архив для Windows x64 с понятным именем, например `VideoCompressor-1.1.0-win-x64.zip`.
2. Внутри — папка с приложением, FFmpeg и короткая инструкция «Как запустить» (текстовый файл на русском).
3. После распаковки приложение запускается двойным щелчком по `VideoCompressor.exe` на чистой Windows 10/11 x64 без .NET и FFmpeg.
4. Приложение ничего не устанавливает и не пишет за пределы своей папки, кроме файла настроек и результатов сжатия. Удаление — удалить папку.

### US-2. Понять предупреждение Windows (P1)

*Как пользователь, я хочу понимать, почему Windows показывает синее окно, и решить, доверять ли программе.*

**Критерии приёмки:**
1. Инструкция в архиве и описание релиза объясняют окно SmartScreen («Система Windows защитила ваш компьютер»): почему оно появляется у неподписанных программ и как запустить («Подробнее» → «Выполнить в любом случае»).
2. Там же — как проверить, что архив не подменён: контрольная сумма SHA-256 и подтверждение, что архив собран GitHub из открытого кода конкретной версии (аттестация сборки).

### US-3. Узнать версию и найти новую (P2)

1. Версия приложения видна в окне (например, в заголовке или разделе «О программе»).
2. Там же — ссылка на страницу релизов на GitHub (открывается в браузере только по нажатию).

## 5. Функциональные требования

- **FR-001** Архив собирается автоматически в GitHub Actions при создании тега версии (`v1.1.0`) из публичного кода — не на компьютере разработчика.
- **FR-002** FFmpeg и ffprobe берутся из официальных сборок, рекомендованных проектом FFmpeg, конкретной закреплённой версии; их контрольная сумма проверяется при сборке.
- **FR-003** В архиве лежат тексты лицензий: лицензия проекта и лицензия FFmpeg (GPL) со ссылкой на исходники FFmpeg.
- **FR-004** У проекта есть лицензия (`LICENSE` в корне репозитория).
- **FR-005** Приложение сначала ищет FFmpeg в своей папке (как в v1, plan §4.1), поэтому встроенный FFmpeg используется всегда, даже если в системе стоит другой.
- **FR-006** Номер версии задаётся в одном месте и попадает и в приложение, и в имя архива.

## 6. Критерии успеха

| ID | Критерий |
|----|----------|
| SC-001 | На чистой Windows (Windows Sandbox, без .NET и FFmpeg) архив распаковывается, приложение запускается и сжимает эталонную запись. |
| SC-002 | Размер архива — не больше ~150 МБ. |
| SC-003 | Релиз создаётся одной командой — отправкой тега; всё остальное делает CI. |
| SC-004 | Для архива релиза доступна проверяемая аттестация сборки (`gh attestation verify`). |
